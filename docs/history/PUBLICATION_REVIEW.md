## 依赖审计结果与已知边界

### 初次迁移修复（历史记录）

首次官方 npm 审计报告 3 个高危、3 个中危依赖项。使用 **不带 `--force`** 的 `npm audit fix --ignore-scripts --registry=https://registry.npmjs.org` 在已有版本约束内更新 3 个包，修复了所报告的高危项。

修复后：

- `npm audit --omit=dev --registry=https://registry.npmjs.org --json`：退出 0，生产依赖报告 0 项已知漏洞。
- 完整开发依赖中仍有 3 项中危记录，来自 `@capacitor/cli -> xcode -> uuid` 同一依赖链；这是 Android/iOS 开发工具路径，不等同于浏览器扩展运行时漏洞。
- npm 建议的剩余修复需要强制变更固定的 Capacitor CLI 版本。本次不执行强制升级、降级或跨主版本 override，也未假称移动端工具链已通过验收。
- 当时已向用户说明上述已知风险，用户明确选择 **先保持私有**；该记录不代表后续已经获得转公开授权。
