## 本轮范围

这是第一轮小范围实现，不是全仓重构完成。保留 Vue + TypeScript、所有既有存储键、账号、收藏、任务和独立页面；不重载浏览器，不连接 QQ，不启动/停止原生服务，不提交或公开发布。

### 1. 注册、展示、启用分离

- YouTube 保持注册，showInDock:false 控制默认入口；商店启用不修改注册中心。
- Dock 的实验卡片从注册中心取 ID、图标、名称、排序目标，注册缺失时不制造无法打开的入口。
- 核心入口默认可用不等于已经挂载或后台正在运行。停用可选入口仅移除 Dock 入口，不负责关闭窗口或停止共享服务。
- 目前 YouTube 的实验入口处理仍是专用分支，尚未实现外部模块热安装协议。

### 2. 商店诚实文案与边界

- 下载并安装/卸载改为启用/停用入口，去掉 280ms 假加载。
- 已启用计数按当前可见目录计算，包含默认核心入口；不再声称清空整个 Dock 或完全纯净模式。
- 批量启用只针对稳定可选组件；实验组件必须单独启用。
- 控制器拒绝未知组件、实验室关闭时的实验启用和核心停用。
- 实验室是展示开关，不是账号授权、私人代码隔离或安全沙箱。关闭实验室保留已启用入口，避免突然中断使用。
- 公开发布前建议单独制作公开构建并排除私人代码及独立入口。此轮未制作公开版本，也未发布。

### 3. 启用偏好的存储与类型试点

- JSON 初读按 unknown 校验，拒绝非字符串数组；无效或无法读取时不允许覆盖原数据，重新打开商店可重读。
- 保存成功后才提交响应式状态并更新 Dock；失败有非模态错误文本，不伪报成功。
- 保留旧 storage key 和未知旧 ID，不迁移账号/收藏数据。
- storage 事件更新其他标签的启用偏好；后续共享 Web Lock 已序列化新控制器的同键写入，按最新值应用修改意图。旧版本页面或绕开控制器的写入仍不受锁约束，其他存储并非跨页事务。
- 此试点没有把全仓存储统一起来，也没有添加 @types/chrome 或改造 Native Host 协议。

## 原生桥消息边界增量

- 范围：background/native-host.ts 的共享 Native Messaging envelope、长连接 requestId RPC、单次消息与 DSH/Pi Web/Pi WSL 调度；新增 native-protocol.ts。QQ owner 的严格单主账号协议不改。
- 已核对仓库 Windows C# 与 Mac Python 宿主回复为 boolean ok，携带 requestId；这是源码核对，未读取部署配置或调用已安装 EXE/远端宿主。
- 回复改由 unknown 校验：必须是非数组对象、ok 为布尔值；running/already/online/launched/copied/deleted 若存在必须为布尔值；error 若存在必须为字符串。不把缺失 ok 当成功，不把字符串 false 当运行中。保留命令特有 payload 和数字型 stopped，不泛化成已完成/已退出。
- 匹配 requestId 的 RPC 先结束，事件批次再检查 Array.isArray 与对象/type/path；非法批次不再因 forEach 抛错阻止正常 RPC 返回。事件异步错误被捕获，不日志记录消息/凭据。
- 长连接请求使用捕获的端口且只发一次；发送抛错立即结束，超时、断线、显式关闭清请求映射与定时器。迟到回复不再完成已结束请求，不重放写入。
- 宿主端口带身份/代次保护，旧回调不覆盖新连接；关闭混合模式清重连与气泡定时器，迟到偏好读取/气泡准备不能重新拉起旧连接。仍保留混合模式原有重连意图，连接重建不等于重发请求。
- 单次 Native Messaging 添加有限等待与同步异常返回；超时说明结果未确认，不当作远端操作已取消，不自动换通道或重试。
- 本地服务调度拒绝继承属性服务名，状态读取必须明确 running；只有 running:false 才发送启动。启动等待状态轮询共享 20 秒预算，异常状态及时返回；只有明确 running:false 才报告停止响应成功。页面打开失败明确区分“服务在运行”与“页面没打开”，不重发启动。unexpected rejection 也返回明确失败。
- 这不是命令级 payload 全量 schema、权限沙箱、原生启动/停止进程身份验证或后台永久保活方案；服务 running 沿用宿主端口检查，不证明登录/业务就绪。
- npm run check / node --check background.js / 修改文件 diff 检查通过；未断言或 E2E，未实际启动/停止 QQ 或本地服务、调用宿主、连接远端、读取账号配置或重载浏览器。
- 下一步：逐项命令 payload 验证与危险操作授权边界；需人工验收顶栏本地服务状态，不能把源码构建当作已部署协议通过。

## 原生命令授权与参数增量

- background/native-request-policy.ts 验证发送者扩展 ID、协议/主机、明确 UI 页面路径及顶层 frame；拒绝网页内容脚本、子 frame、壁纸 sandbox 和 incognito 来源。页面查询参数/hash 不改变原页面许可；不是鉴权 token 或用户手势证明。
- petNativeCommand 原来任意命令转发且不给 UI 返回结果；现只允许当前调用者使用的 dsh-status/pi-web-status/pi-wsl-status。通过带 requestId 的 nativeRpc 返回真实状态，保留共享连接。拒绝通用入口的 QQ 启停、任意写入/升级/目录操作，不允许额外 payload 或 requestId 穿透；内部 tab-manager/气泡的 postPetNative 保留。
- nativeMessageRoutes 与 agentService 使用同一来源限制，AI 原有仅主标签页限制继续保留；QQ owner 专用启动/停止/身份校验不变。
- 手机消息与通知的 limit 必须是范围内安全整数，默认值仅用于缺失字段；app/model/path 按类型、长度与控制字符校验，不把对象转字符串、不默默截断路径。中文/空格不改写；路径格式校验并非目录沙箱。
- 已移除无当前源码调用者的后台 RPC：logicWeaverSyncGet、logicWeaverSyncPut、n8nGitHubUsedSync、mobileWatcherSetFolder。它们的旧实现会把无效数组变成空数组或把无效参数变成字符串；不保留无作用写入口。
- 普通备份经 SyncService/OptionsService 直接 Native Messaging 调用，宿主 C#/Python 的 sync 命令及存储未删；GitHub profile.service 仍调用 n8nGitHubUpdates，因此保留该读取路由。
- AgentLaunchers 的三项原生状态采用明确 ok/running；查询失败显示 error 而非“已停止”。查询与用户操作有本页版本保护，旧结果不覆盖更晚启停或查询。
- npm run check / node --check background.js / 修改文件 diff 检查通过。未调用宿主、实际查询状态、读取短信/文件或账号配置、启停服务、重载/提交/推送；无断言/E2E。
- 限制范围仅后台消息入口：扩展自身页面仍拥有 manifest 原生权限，可直接 sendNativeMessage；6198 网关、OptionsService/SyncService 的直接原生调用不在此隔离内。不能宣称全扩展权限沙箱、所有 QQ/外部服务控制已安全。
- 下一步优先治理直接原生调用的超时/结果验证及同步备用通道重复写风险；真实手机读取与三项顶栏状态仍需人工验收。

## 直接 Native Messaging 与同步重复提交增量

- 将通用 envelope 校验移至 core/native-protocol.ts，后台与页面共用；background/native-protocol.ts 不再保留重复实现。新增 core/native-messaging.ts，只向当前已登记的 com.logicweaver.arkpets 宿主发送一次。
- OptionsService/SyncService 的直接调用复用有限等待（95 秒）、显式 ok/布尔标志校验、同步发送失败返回、定时器清理和迟到回调忽略。仍消费迟到 Chrome lastError，不记录实际消息/凭据；超时不撤回原生已接收工作。
- SyncService 删除没有当前注册者的 window.callNativeHost 委托与 com.logicweaver.host 自动备用重发。当前 Windows/Mac 安装使用 arkpets ID；不会在失败后自动安装、切换宿主或重新上传。
- SyncService 仅允许 sync get/put，本页 pushConfig/pullConfig 整个准备/传输/恢复互斥；并发拒绝而非排队重试，finally 释放等待门禁。保留普通备份 V2、58KB 检查、凭据排除、旧键和恢复规则。
- 拉取的 data 先校验对象再取 value，随后原 parseSyncBackup 在写入前验证。原生超时或失败不触发恢复，Mac 明确 cloudSynced:false（只有本地快照）不再显示云端备份成功。
- OptionsService 仅允许原有 Git 检查/应用命令。settings/git-native-reply.ts 校验检查字段（hasUpdate/文本/非负整数）；远端检查 warning 不再显示“已最新”或启用更新按钮。View 检查/应用互斥，重新检查先清旧可更新状态，应用后必须重新检查才能再次应用。
- 当前门禁是单页等待/操作互斥，不是跨页事务、请求幂等键或超时后的永久未知状态锁。手动再次提交仍需用户核对，宿主部署和远端持久化 ACK 尚未全面验证；直接原生权限不是沙箱。
- npm run check / node --check background.js / 修改文件 diff 检查通过，产物由构建更新；未读真实配置/备份/凭据，未执行原生 Git fetch/pull、备份上传恢复、启停任何服务、自动重载或提交推送；无断言/E2E。
- 后续优先处理跨标签配置更新与恢复的实际冲突边界，不机械统一全仓存储；Git 与 Native 同步真实交互仍待人工验收。

## 商店跨标签偏好写入增量

- 原控制器按 state.installedIds 缓存保存整表，迟到 storage 事件或同时修改不同入口可能丢失另一个页面的变更。install/uninstall/toggle/批量动作改为修改意图，持有同源 Web Lock 后重读原键，仅应用目标增删。
- 共享锁名称绑定 logicweaver_installed_dock_modules；锁内本地读取/校验/变更/保存/回读为同步代码，不插入 await。每页 isSaving 拒绝重复提交；等待最多约 10 秒，定时取消并校验实际截止时间，超时或无 Web Locks 时拒绝写入，不降级成不安全覆盖。
- 个别启用/停用只改指定已知 ID；批量启用仍排除实验组件，批量停用只删除当前商店管理的可选 ID，未知旧 ID 和已存核心偏好保留。实验启用在锁内读取最新实验室开关。
- 每次打开重读偏好；成功保存并回读核对后才更新 Dock。读取失败拒绝写；保存未确认保留当前 Dock，要求重开核对，不自动重试/回滚覆盖其他页。
- 商店保存期间只禁用写入按钮、显示非模态状态，仍能拖动、关闭与操作页面外部；Dock 右键停用也等待同一控制器结果，失败用既有通知说明，不默默当成功。
- 保留旧存储键和数组格式，无迁移/删除真实数据、无新增框架/轮询。锁只约束采用新控制器的同源页面，不保护旧版本页面/扩展外部写入或全仓恢复事务。
- npm run check / node --check background.js / 修改文件差异与空白检查通过；未断言/E2E、打开或刷新实际浏览器、修改真实偏好/账号/收藏。
- 人工验收需两个标签页都先手动刷新以使用新控制器；分别改不同可选入口，看最终是否都保留；确认保存中按钮暂禁用、Dock 右键停用反馈正常。不要清空存储或人为损坏数据。
- 下一步：全局设置只提交用户编辑字段，并检测其跨页旧草稿冲突；收藏/任务等大范围数据暂不迁移。

## 全局设置旧草稿保护增量

- 发现开关即时保存也发送整份表单、头像、歌词、快捷键和书签过滤旧快照；现即时动作仅提交自身字段，统一保存按成功初读的界面基线找改动项，未编辑字段不写。
- SettingsView 的头像/快捷键/书签过滤即时写入统一经过 OptionsService.saveSettings；仅允许全局非敏感白名单及既有四个偏好键，保留格式与账号隔离。
- 新设置页面持同源 Web Lock，读取待修改键的最新存储值，逐键对比原始存储基线；若最新值既不同于基线也不同于拟保存值，拒绝整个本次提交，保留草稿，不自动覆盖/合并。歌词仍以整个存储键为冲突单元；后续条目增量已将快捷键/书签过滤细化到ID，见下节。
