# 聊天室会话与授权层级

> 本文对应当前私有 HTTP 服务。旧 `lw_chat_session_v1` 本机导航记录或 `/ws?...` 样式的会话字符串不能当作现行授权来源；P2P/WebSocket 方案见已标记的历史文档，不按旧方案恢复连接。

## 当前来源

- `private-chat-config.ts`：`lw_private_chat_v1` 保存非敏感 origin、父聊天室 room 和本机 UID；配置读取失败与不存在分别报告。
- `private-chat-client.ts` 装配 `private-chat-credentials.ts` / `private-chat-http.ts`：Token仍存于原独立IndexedDB，库/键/邀请格式不变（边界见 [CHAT_TRANSPORT_BOUNDARIES.md](CHAT_TRANSPORT_BOUNDARIES.md)）；邀请必须属于当前聊天 ID。导入新邀请重新认证；不能拿旧 UID 的邀请用于新身份。
- 授权层级是服务器 origin → 父聊天室 room → 组织空间 space → 子房间 channel。空间组织房间，不扩大父聊天室权限。
- `privateChatState` 的共享目录由 HTTP 服务返回；旧本机群/频道操作不等于给所有成员建立共享空间或房间。

同步调度现由 `private-chat-sync.ts` 拥有世代/计时器/读取会话，待发写入由 `private-chat-outbox.ts` 独立协调；父认证仍在门面，同步页现由独立reader/projection完整解析后应用（见 [CHAT_SYNC_PAGES.md](CHAT_SYNC_PAGES.md)），既有类型继续从门面重导出。分层及未迁移边界见 [CHAT_CLIENT_LAYERS.md](CHAT_CLIENT_LAYERS.md)，不代表真实切房或消息验收已完成。

## 切换边界

- 同一已认证父聊天室内部切房取消旧房间同步并使用新 scope；不应清空整个服务身份或把已连接闪回未配置。
- 换 origin/父聊天室/UID/凭证、明确断开或鉴权失效时重新认证。主动取消请求不当作网络故障；旧响应不得覆盖新房间。
- 默认 main 房间保留；其他共享空间/房间移除是归档而非删除消息。当前房间失效时返回默认房间，原待发消息仍绑定原目标，不能改投其他房间。
- 历史 scope 由 UID、会话 endpoint 与父房间生成；子 channel 被编码进 endpoint。`privateEndpoint()` 的 WS 样式仅是历史分域标识，实际消息请求为 HTTP。
- 停用本机连接不清空历史和凭证；清浏览器数据或换浏览器资料可能产生新聊天 ID，需要服主为新 ID 创建邀请，不可覆盖原身份模拟小号。

## 一起听：状态恢复与实时副作用分离

- `together-listen-model.ts` 是纯状态投影与有界消息回执，不通知、不播放、不读写存储、不广播；`together-listen.store.ts` 仅对有效当前会话的新事件执行副作用。
- `chatHistoryLoadState` 明确报告对应 scope 的本地历史读取结束；移除固定 600ms 后重放“最新派对消息”的启动定时器。历史只恢复已缓存状态，不提示“刚刚结束”、不自动播放，也不沿用旧的全局 `beaver_party_joined` 标记自动加入。
- 网络消息附带 scope、子房间、服务器 sequence 和 history/live/self 来源；每次同步世代的首次分页追赶全部作为 history，直到 hasMore 排空，不能因已有非零游标就把启动积压当实时事件。普通聊天提示也不能给这批旧派对消息补发通知。
- 回执按包含 UID/服务器/父聊天室/子房间的 scope 与消息 ID 去重，并拒绝倒退的服务器顺序；只保留本页最近 32 个 scope、每个 512 个 ID，不宣称跨设备或跨页面全局恰好执行一次。刷新后的恢复静默由来源隔离保证，不靠永不清理的去重表。
- 自己已应用的本机动作登记回执；同 UID 其他页面的消息可以静默更新状态，不重复本页播放或通知。切会话清理派对 UI 与本页加入态；显式操作后晚到的启动历史不覆盖用户意图。旧邀请卡片不能回滚已结束/已换曲的状态。
- 音频提交检查会话与读取代次；退出、切房、结束后的迟到音源与 metadata 回调不再重写新的播放目标。音乐/电台服务增加可选提交守卫；未传选项的原调用保留默认播放行为。结束广播不再经过重新起播分支，切歌广播不等待本机音源解析。
- 这是客户端状态边界，不是服务端 DJ 权限或权威派对租约。历史只代表最后可见的缓存状态，不证明派对仍在线；已开始的独立音乐不会因切房被强制停止。真实双端同步、自动播放限制和并发操作仍需单独人工验收。

## 验收与未覆盖范围

- 同父聊天室好友接口已存在，不沿用“尚无认证/好友/服务端落盘确认”的旧描述；但跨服联邦未提供，落盘确认不等于对方已读。
- 人工检查邀请预览与 UID 绑定、切房身份保持、归档回退、历史/待发作用域和不同配置的身份隔离，均须另获授权。
- 本文不宣称多标签导航偏好完全一致、旧缓存自动恢复或关闭浏览器前所有待存记录一定落盘。源码构建与浏览器/真实服务验收分开报告。
