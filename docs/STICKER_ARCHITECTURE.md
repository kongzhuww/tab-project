# 图库职责与资源边界

架构升级第二阶段。这里描述当前源码，不代表真实图库、权限弹窗、删除或浏览器视觉已经验收。

## 分层

```text
表情包模块 / 独立工具 / 聊天室选择器
                   |
       services/stickers.service.ts
       (模式、任务、确认、分页、展示协调)
          /            |             \
  directory-reader   library-       preview-resources
  original-files     repository      image-preview
   磁盘原图          浏览器元数据       可重建预览
```

| 文件 | 职责 |
| --- | --- |
| `src/stickers/sticker-types.ts` | 物理目录树与图片元数据契约；不依赖UI或service |
| `src/stickers/directory-reader.ts` | 只读元数据扫描及树查询；每次调用自有计数，不与迟到扫描共用计数器 |
| `src/stickers/original-files.ts` | 原图读取、读权限检查、显式写权限申请、单文件写入及受核验的单文件删除；不修改索引或UI |
| `src/stickers/library-repository.ts` | 句柄数据库连接、根句柄读写、索引载入/协调/保存/查询及已删除图片的索引清理；不操作磁盘原图 |
| `src/stickers/library-index.ts` | 现有真实根绑定、UUID匹配、revision-CAS持久化实现，以及分类投影/编辑与备份校验；不依赖service类型 |
| `src/stickers/folder-layout.ts` | 既有旧分类展示映射，仍只用于首次索引建立的兼容 |
| `src/stickers/preview-resources.ts` | 每个门面实例独立的预览生成队列、Blob URL缓存和回收；目录模式与旧内置库共用 |
| `src/stickers/image-preview.ts` | 既有缩略预览编码算法，保留小GIF动画与尺寸限制，不改写原图 |
| `src/stickers/sticker-db.ts` | 保留旧内置Blob库的独立存取和分类事务，不与目录图库自动合并 |
| `src/services/stickers.service.ts` | 原兼容门面与类型重导出；用户确认、当前源、读写调度、虚拟分类动作、导入解析、复制、分页及View state投影仍由它协调 |

门面不再自己打开句柄数据库、执行File System单文件写入/删除或创建/释放展示Blob URL。旧公开方法保留为委托，不要求现有调用方改用底层模块。仍有业务协调逻辑，不宣称整个service已改成无状态薄壳或去除全部any。

## 不改变数据与用户意图

- 不更换数据库名、版本、object store、根句柄键、通知键或分类/UUID/缓存格式。
- 不扫描真实用户图库作开发验收，不自动重新选目录、申请写权限、移动/复制/合并或删除原图。
- 设置页选目录仍是read；目录拒绝授权不偷偷切换内置库。新导入仅在用户动作授权后写入原图库根目录，再登记到选定的虚拟分类。
- 分类删除仍只改索引并保留图片。“删除图片”仍先逐张危险确认、申请写权限，再核对当前真实根、resolve结果、实际文件身份及已捕获的大小/修改时间，最终仅removeEntry一个文件名，绝不递归删目录。
- 磁盘删除成功后才清理索引；清理失败提示原图已删除而索引未确认，不伪装回滚。索引备份不含原图，不能恢复磁盘删除。
- 写入已经开始后，隐藏页面或更换源不代表磁盘回滚。失败/超时不自动重试，不改投新目录。
- 索引继续使用原有根句柄身份与revision-CAS；冲突要求刷新，不覆盖其他页的修改。既有失联关系、首次旧分类映射和备份恢复规则保留。

## 设置界面与展示状态

用户已确认将原独立“本地图库”设置并入“文件夹与存储”，作为“表情包图片文件夹”子项，与B站缓存目录集中展示。旧设置调用别名仍归一兼容，模块入口定位相应子项；不迁移句柄/图片/索引或合并授权。知识库只提供返回原模块的受保护入口，未迁入知识库选择表单。用户已确认保留目录图库能力及精简布局：未选目录提供主要选择按钮；关联后显示短目录名/整库数量、更换与小刷新，明确读权限不足时才显示重新授权。分类备份/恢复/旧隐藏兼容操作放入默认折叠的高级管理，独立写权限按钮及处理函数移除；写权限仍只由原有显式原图变更路径申请。

`sticker-board-store.ts`新增纯展示字段rootName、libraryImageCount、needsReadPermission；service在owned读取/current检查后投影。数量取整库树或内置库全库统计，不取当前分类的totalCount，不解析folderPath文案猜权限；未知数量为null而非虚假的0。这些字段不更改持久化键/版本/索引格式。无权限/失败/配置改变时不会静默切换源或清理用户图片；不为设置展示另解码整库预览。

## 预览资源所有权

- 原图字节与可重建的小预览分开；复制、聊天选图和导出不拿缩略图代替原图。
- 每个门面实例一个资源管理器，不跨根或跨页面共享相同相对路径的URL。
- 原图读取/预览生成最多2个同时在途，包含换页后尚未结束的旧任务；待处理队列失效会立即释放等待者。小GIF直接保留原字节的既有策略不变，浏览器自身img解码不由这个队列控制。
- 当前页只保留需要的URL，最多120个；目录、分类、页码变化会使旧队列失效并回收不需要的URL，dispose清空全部。
- 原生文件读取与createImageBitmap未必能物理中止；失效后只停止排队和发布，等待已有操作自然结束并清理bitmap，不假称已撤回底层操作。
- 预览失败仍保留图片索引条目，不能当作原图不存在或自动删除图片。

## 读取与故障边界

- 目录扫描保持最多6层、2万张；单批原生元数据读取16个，单图读取/导入25MiB，一批导入50张的原规则保留。
- 新仓储的连接等待最多15秒，阻塞/失败不重建数据库；迟到成功连接会关闭。根句柄只在事务完成后报告读取/保存结果。
- 后续第三阶段已给目录/内置库owned读取接入60秒整体等待预算；不是给所有底层事务/文件系统调用增加物理取消。根检测移交到内置库会开始新的读取预算；已被接受的元数据事务仍可能完成。
- 门面现通过core/read-session.ts管理读取归属，并保留readVersion、AbortSignal和活动视图业务条件。内置库组/统计/分页/预览等待、空页与失败均有迟到提交检查，旧任务finally不能清新任务的loading。
- 第三阶段首批接入与未迁移范围见 [READ_SESSIONS.md](READ_SESSIONS.md)；没有重写全应用的loading/owner机制，也不作性能、零竞态或跨进程恰好一次保证。

## 验证口径与人工确认

开发验证限于类型检查、多入口构建、生成脚本语法和差异检查，禁止断言/无头E2E，未操作浏览器或真实图库。

用户可在刷新后先做非破坏性确认：现有分类/数量是否一致、连续换页后预览是否正确、关闭再打开和聊天室选择器是否正常、只读目录能否展示。权限恢复、导入、索引备份/恢复及真实删除只在用户另行授权并选用可丢弃图片后验收；不要为了验证重构而拿原图做删除测试。
