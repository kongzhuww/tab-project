# 聊天室安全边界与发布检查

> 当前链路是 `private-chat-client.ts` 与 `server/private-chat/server.py` 的 HTTP 增量同步；不是历史 WebSocket/P2P 中继。入口见 [CURRENT_STATE.md](CURRENT_STATE.md)，部署见 [私有服务说明](../server/private-chat/README.md)。本文是源码边界，不是完整安全审计或双端验收结论。

## 当前实现

- 不内置默认公共聊天服务。非敏感连接配置是 `lw_private_chat_v1`，包含 origin、父聊天室与 UID；Token 单独保存在本机 IndexedDB 凭证库，不放请求 URL。停用连接不删除历史或凭证。
- 请求带 Bearer 凭证，拒绝重定向并不发送浏览器 Cookie。公网部署应使用 HTTPS；配置校验目前接受 HTTP/HTTPS，不能宣称客户端强制所有场景使用 TLS。
- 服务端以父聊天室凭证校验身份与权限；成员邀请绑定 UID、有期限且可撤销。UID 本身不是授权凭据。邀请只是编码后的访问凭据，不是加密文档，不能公开分享或写入日志。
- 服务端存储文字、白名单分享卡片和受限的内联图片消息；不提供公共图片下载端点或音视频文件上传。普通消息提交体限256KiB，图片请求/消息限2MiB、解码字节限1MiB、约1600万像素且边长不超8192，客户端响应仍限2MiB。image_policy.py 校验Base64、栅格文件头与尺寸，不请求远程URL，不接受SVG，不等同完整图片解码/病毒检查。必须升级服务并返回 imageMessages=1 能力；图片内容及可能的元数据会被服务器看到和保存。
- `chat-security.ts` 对消息与外链执行字段校验；远端数据不是任意 HTML/脚本。服务器仍须独立校验，不能以客户端校验替代鉴权和限流。
- HTTP 同步中已包含成员动态、在线信息及同一父聊天室内的好友请求/关系。活动来自扩展内播放/工作区，受 `shareActivity` 控制，当前缺省值为开启；不要沿用“默认不分享/没有 Presence”的旧说明。关闭效果和权限隔离仍需授权的双端验收。
- 历史、待发队列与同步游标按身份/服务器/房间作用域隔离。服务端落盘确认不是成员已读，也不是端到端可靠投递保证。

凭据仓储与HTTP现已独立：API路径限定已校验的目标origin，room/channel从快照设置；等待凭据后过期不再发起请求。原凭据库/键与邀请格式不变，常见原生URL/JSON/网络错误不回显请求或响应片段；预算、写入不确定性与未覆盖范围见 [CHAT_TRANSPORT_BOUNDARIES.md](CHAT_TRANSPORT_BOUNDARIES.md)。这是源码加固，不是完整安全审计或真实服务验收。

同步页现以unknown完整解析身份/消息/目录/成员/好友结构后才持久本页，结构失效清发送能力而非沿用旧协商继续发送；投影和通知受current守卫，活动字典使用无原型对象，监听异常不打印原始payload或错误。明确预算与未覆盖输入见 [CHAT_SYNC_PAGES.md](CHAT_SYNC_PAGES.md)，不代表所有管理API已做统一Schema或全应用日志审计。

## 不提供的保证

- 不提供端到端加密；服主/服务器运营者可能读取消息及分享动态。本地存储不代表应用级加密。
- 同聊天室好友关系不等于跨服身份互认或联邦。昵称、自报 UID 和缓存名片不能代替服务端凭证认证。
- 远程头像或卡片图片请求会接触第三方服务器；`no-referrer` 不隐藏访问者网络地址。
- 不承诺浏览器数据永久保留、无限离线投递、DDoS 防护、零丢失或图片解码安全。隐私、限流和服务升级需分别审查。

## 发布与人工验收

- 用 `npm run release:build` 从源码在隔离工作区生成发布包；不直接复制开发目录或带历史 chunks 的 generated 目录发布。
- 发布目录需检查私有地址、密钥、本地配置与日志；扫描零命中不等于完整安全审计。已泄露的有效凭证须由服务方撤销/轮换。
- 人工验收另获授权后检查：缺配置/缺凭证/UID 不匹配/401/网络失败的区别、同一聊天室切房隔离、分享开关、好友请求权限、历史与待发失败反馈。
- 类型检查和构建不替代浏览器、真实服务或安全验收；不运行历史断言/无头 E2E。
