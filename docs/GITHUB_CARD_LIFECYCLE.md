## 当前补充：详情复用 GitHub 账号鉴权

- 已定位旧 detail-read.ts 固定匿名请求：公开目标 README 仅约5.6KiB，但本机匿名 GitHub API 返回403、额度60/剩余0，不能归因文件过大或单纯超时。诊断未读取插件 Token。
- 将现有 ghUser/ghToken 读取提到无 service/store 依赖的 account-settings.ts 叶模块，settings.ts 保留同名导出。详情打开/重读时由统一客户端读取一次当前账号快照，元数据/README/中文候选共用该次鉴权；设置读取失败不悄悄降级匿名，仅确实未配置 Token 时走匿名。
- Token 仅放到固定 https://api.github.com 的 Authorization，禁止重定向/Cookie/Referrer，不送 raw 域、镜像、Jina 或 AI，不进入 View state/日志/新缓存。此轮没有读取实际插件存储或用用户 Token 做验证。
- 区分401无效凭据、403/429额度/频率、403权限/SSO、404不存在或无权、大小、编码、超时与网络失败。认证/限额已明确失败则不继续浪费后续详情请求；可选中文读取失败保留已取得的默认 README。
- 单次HTTP12秒、整体45秒仍保留；账号设置等待也可中止，迟到结果不再发送网络。JSON流式读取最多2MiB、Base64解码README最多1MiB，不靠无界 response.json 等待完整大响应。
- 详情打开期间仅监听账号键是否改变，不读取变更值；账号改变中止旧请求并清除旧正文，等待显式重读，不自动重新发请求；关闭详情移除监听。没有引入跨账号 README 缓存。
- 类型/构建、语法和差异检查用于源码验证，真实插件鉴权与卡片显示仍待用户刷新验收；不操作浏览器或读取/打印 Token，不执行断言或无头 E2E。

## 第二阶段：账号初始化、分页与完整列表读取

- View拥有读取signal；隐藏/卸载使会话失效，fetch与重试等待可取消。新loadGitHub淘汰前一账号会话；缓存、账号验证、配置、网络/body及缓存写后回调检查会话身份。单页再有独立版本/Abort，旧页finally不会结束新页状态。
- 初始化/目标页/全量补全被中断后，返回卡片可继续未完成工作；初始化可能从账号/配置重新读取，全量补全从第一页重新开始，不宣称断点续传。失败的初始化保留待初始化意图，可在返回或手动刷新时重新请求；完整补全已结束失败则等显式刷新。
- 请求快照固定baseUrl/headers/token，单次GET包含body的15秒上限；有Token最多2次、无Token1次，4xx/格式错误不自动重试，900ms等待可取消。不重试Star远端写。
- Token模式先读取GitHub /user的账号ID，缓存format3 owner为github-id:<ID>；公开用户名沿用user:<lowercase>并兼容匹配的format2缓存。旧token:me/token:用户名无法证明账号归属，不再恢复，原存储未删除。缓存不保存Token或其指纹；离线无法确认Token账号时不冒用旧缓存。
- 初始分类规范化只在内存执行，移除loadGitHub打开时的隐式savePersistence。显式分类/备注写入逻辑保留；其完整并发一致性尚未治理。
- Star/Unstar开始前取消所有旧列表读，同页远端Star写互斥，写期间禁止新读或切换服务账号；请求本身不随隐藏取消。配置保存可以已完成，但账号初始化延后至返回/刷新；设置文案不把延后当同步成功。该门禁仅为读取整合所需，不代表完整远端写工作流已治理。
- 缓存写提交前核对身份、payload固定owner；已提交chrome.storage无法物理撤回，也未实现跨页原子事务。源站可能已经处理被Abort的GET，不宣称消除全部后台流量。

## 第三阶段：Star 提交与确认快照

- 新增star-request.ts：固定GitHub端点、仓库路径校验、禁Cookie/重定向，PUT/DELETE只发送一次、等待25秒；成功、4xx拒绝（408除外）、网络/超时/5xx等结果未知分开。隐藏不撤回已提交写；超时abort仅结束等待，不能证明服务端未执行。
- 单项与批量确认由service管理，确认前固定仓库副本、账号revision、View signal；等待期间加载账号/隐藏/重新进入使确认失效，不晚提交到新账号。批量写持有整个批次同页门禁；每项发送前再检查，隐藏/账号加载意图改变后不发剩余项，已提交项仍完成结果处理。
- 批量只从选择中移除远端已确认项，报告实际确认数量，拒绝/未知/本地缓存失败停止后续，不清空后来新增选择、不伪报全成功。确认成功后自动退出批量模式已移除。
- 远端确认后才更新本页成员关系，缓存失败独立提示“GitHub已确认、本地未确认”，不反向回滚或重发远端写。Star布尔返回只代表远端确认，不代表缓存已持久化。
- 取消Star不再删除ghMap或调用savePersistence，本地分类归属与备注保留；它们不会让已取消仓库继续出现在列表。这是明确的保留本地资料策略，不是已经完成全部分类写入治理。
- 未知结果记录在当前service内存，按验证过的账号owner归属；当前账号有未核对项时拒绝新Star写，状态栏保持警告。切账号不清其它账号标记，但整页关闭/刷新会丢失内存标记，未新增持久化操作日志/跨页锁。
- 原来hidden/display:none的gh-refresh-btn恢复显示为“刷新 / 核对”。显式点击先GET核对未知项（15秒、可取消、不重试），404还需仓库GET成功才作当前未收藏处理；读失败或缓存未保存保留标记。暂停其它旧列表读，核对结果及缓存完成后才解除本页门禁，再重新统计/读取当前列表。普通隐藏恢复不自动解除未知标记。
- 核对仅证明当次API可读状态，不保证已超时请求永不晚生效；不重发/反向补偿旧写。保留缺配置时显式打开仓库的入口；写入反馈留卡片，不再以全局Toast打断其它页面。
