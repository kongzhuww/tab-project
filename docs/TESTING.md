# 测试与回归验证

## 现行规则

根 AGENTS.md 已按用户最新要求解除断言/无头 E2E 禁令。允许分层引入测试，但不得使用日常浏览器资料、真实凭据或云端写入作默认验证。本文不将旧的“本轮未运行测试”历史记录改写成已经完成。

## 当前命令

```sh
npm test
npm run check
git diff --check
```

- `npm test`：Node 内置 test runner（Node 22+），当前为发行策略回归；无需安装新测试依赖。CI 与 Release 工作流均在 npm ci 前执行，依赖镜像不可达不应阻止这组零依赖测试。
- `npm run check`：现有 TypeScript 检查及 Vite/后台构建，不冒充功能测试。
- `npm run release:build`：按需验证隔离发行构建，生成本地副本，不上传或发布。

## 已覆盖：发行策略

`tests/release-policy.test.mjs` 从 `.github/workflows/release.yml` 的标记区提取并执行实际内联校验，使用受控文件系统、ZIP manifest 读取结果及 GitHub API 响应；没有真实 Token、外网请求或发行操作。真实 SHA256 运算保留。

覆盖新发行、普通/注解 Tag、手动触发版本推导、已有发行/草稿/预发布拒绝、鉴权/限流/服务异常、网络失败、异常响应、版本与 Tag 不一致、缺少或多余附件、非普通文件、ZIP 哈希损坏、校验和路径越界、多校验项、构建来源不匹配、manifest 格式/版本不匹配、缺少或移动 Tag、注解链有界处理。另检查工作流不含覆盖/编辑/删除旧发行、写权限任务不检出源码或安装依赖、Latest 参数及 CI/Release 测试入口。

工作流结构检查是针对关键契约的文本检查，并非完整 YAML 语义校验。可在后续维护中补充 YAML/Actions 专用静态检查，不以当前断言声称覆盖任意等价写法或所有工作流错误。

## 未覆盖与下一步

- 未使用真实 GitHub 发布凭据或真实仓库创建/竞争/删除发行；未验证服务端不可变发行或 Tag 保护。
- ZIP 提取返回值由 fixture 提供，非真实 ZIP 解包集成测试；发布 shell 与 GitHub API 服务行为仍需独立受控集成验证。
- 当前不是全应用测试套件：模块注册、权限必要性、Manifest 所有入口、构建产物完整性、UI、第三方接口及浏览器交互尚未由本组测试覆盖。
- 后续按优先级补模块/入口契约、权限审计后的白名单、纯逻辑单元测试和独立配置的 E2E；不要先固化未经审计的宽权限或旧文档为“正确基线”。

新增测试应记录目的、fixture 来源与边界，失败先定位，不为绿灯删除有效检查或硬编码用户私有数据。真实接口、浏览器、部署与商店审核仍分项报告。
