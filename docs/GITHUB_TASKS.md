# GitHub 仓库详情任务栏（源码实现，待人工验收）

## 使用流程

1. 打开 todoist，在一个实际分组的“更多”菜单选择“设为 GitHub 任务区”。同一浏览器配置只指定一个目标；再次选择可取消。默认未分组列、今天/逾期等虚拟列不能作为目标。
2. 打开 GitHub 仓库详情，点击标题栏“任务”，在右侧创建栏填写名称、描述和可选截止日期/时间。
3. 点击“创建任务”。名称、描述、截止日期及捕获的项目/分组 ID 提交 Todoist；仓库卡片单独保存本机，不注入描述、不修改 GitHub。
4. 创建成功点击“在插件中打开任务”会关闭仓库详情，并通过既有任务路由打开插件内 todoist 及任务详情，不跳外部官网。任务详情“关联仓库”显示同一张本机卡片。“继续创建”仅开始下一份空白草稿，不删除已创建任务或关联。

仓库详情已删除 Clone、px 命令复制、放大切换及公开重读操作/专属状态与样式。正常打开仍读取 README；读取暂停/失败后提示关闭并重新打开，不恢复旧工具栏。代码块复制和图片查看保留。

## 代码边界

- `src/github/GitHubRepositoryTasks.vue`：创建栏、只读分组预检、提交/回执及关联补偿。
- `src/todoist/github-task-target.ts`：目标分组的本机选择与创建互斥状态，不保存 Token。
- `src/todoist/repository-links.ts`：任务到仓库快照的共用存储；`TaskRepositoryLinks.vue` 与创建栏复用此层。
- `src/todoist/ReminderPicker.vue`：本机提醒快捷项、日期、AM/PM 时间、预览与保存错误。日期/时间复用现有选择器的嵌入模式，不再放置原生 datetime-local 控件。支持10分钟后、1小时后、明早9点；需确认保存，不在选择时直接设闹钟。

## 写入和失败保护

- 目标由真实项目 ID 与分组 ID 定位，不按“github”等名称猜测、不自动新建分组或改投其他列。提交前 GET 指定分组核对归属与归档状态；配置变化、账号变化、页面隐藏则不开始 POST。
- 跨标签页使用同源 Web Locks；创建使用 UUID `X-Request-Id`，但不依赖此头声称服务端恰好一次。提交前记录本机待核对回执；若存储失败，不发送创建请求。
- 单次 POST，不自动重试。不确定提交后保留原仓库、任务名称、目标和请求标记；重新打开也先要求核对。只有用户明确选择“我已核对，允许新建”才解除此本机保护。
- 已有任务 ID 时只允许重试本机关联，不再次 POST。回执保存失败不假称任务未创建；返回分组不一致提示核对，不重投。
- 解除保护同样持有跨页锁并核对请求 ID，不允许旧窗口清掉另一窗口的新回执。创建期间阻止关闭/切换仓库及切换任务区；已提交请求不因页面隐藏被假称撤回。
- 配置和卡片仅本浏览器本插件保存，不跨设备同步。目标分组删除、移动或归档后需重新选择。不在本轮扫描或清理既有凭据、远端任务、旧回执或仓库卡片。
- 草稿仅在当前创建栏内存中；关闭创建栏会丢失尚未提交的文字。回执用于防重复，不是通用离线草稿/任务历史。不同浏览器、设备或客户端间没有统一锁，不能承诺全局无重复。

## 人工验收清单

- 明亮、纸面、暗色主题下打开提醒，检查快捷时间、手输 AM/PM、15分钟推荐、非法/过去时间和通知权限失败。
- 指定一个真实分组后打开仓库详情，“任务”在右侧展开，目标正确；取消指定后不显示可提交表单。
- 明确提交一个可删除的测试任务，核对名称/描述/日期/分组以及任务详情关联卡片，再自行决定是否删除测试任务。
- 两个标签页重复点击、网络失败后重开、关联存储失败时确认不会自动再创建。窄窗口和拖到右侧后打开任务栏，核对视口避让。

只运行类型检查、构建、差异和生成后台语法检查；不运行断言或无头 E2E、不自动打开浏览器、不使用真实账户接口、不提交或发布。构建通过不等于上述视觉、通知和云端写入已验收。
