# 同步页：完整草稿与当前会话应用

本阶段仅改前端源码与文档，不操作真实API、凭据、数据库记录、浏览器或服务部署。类型/构建通过不等于真实同步、旧服务互通或多窗口验收。

## 职责

- `private-chat-sync-reader.ts`：从unknown响应生成完整的PrivateChatSyncPage，含身份、顺序消息、能力、共享目录、成员、好友与请求；纯计算，不import运行时状态或读时钟。parseRooms/parseSpaces也供原目录入口复用。
- `private-chat-sync-projection.ts`：负责已持久页的事件来源、消息合并、未读与通知候选、成员/好友/活动投影及当前会话提交。状态与回调经ports显式注入，不反向import门面，不持有HTTP/数据库/轮询计时器。
- `private-chat-client.ts`：保留公开兼容入口、父认证所有权与装配；单轮串起请求、校验、原历史事务、本人消息回执与投影，再触发原独立待发协调器。
- `chat-security.ts`：原normalizeMessage/Activity/UserInfo单参数入口不变；新增显式now的At变体，便于reader在一个时刻完成确定性规范化，不破坏已有array.map(normalizeMessage)调用。

## 处理顺序

1. 捕获原scope/channel，读取游标并请求HTTP页；保留25/20秒单轮等待及原请求预算。
2. current后以显式now解析完整草稿。先校验所有本页必需业务字段，不能在消息已保存、游标已推进或通知已发布后才解析目录/名单。
3. current后调用原commitRelayPage事务，一起保存消息与游标；原事务仍以Math.max避免游标倒退。不改库、键、队列或迁移策略。
4. 鉴权同步返回的本人消息仍可证明服务器保存；尝试在原scope记录回执。回执本地保存失败保留真实存储提示，停止等待不回滚已接受事务。
5. 投影前再次检查current，按scope/channel/sequence发布history/live/self上下文，再构建当前可见状态投影。监听按每条消息的订阅快照分发，并在各回调前检查current。
6. 同步、无await地按字段检查current后提交；能力/目录完成后由门面记录父认证，再应用角色/成员/好友和连接状态。首次追赶只有完整应用且hasMore排空后才标记live。
7. 提交后发布原策略筛选的通知，逐条检查current/窗口可见；回调异常只记固定类别，不把通知错误当网络故障重试。成功返回后才触发独立outbox扫描。

无效页不入本页历史、不推进游标、不发本页事件/通知，也不启用其角色/名单。作为安全失效处理，会清除当前发送能力，等待下一有效同步恢复；不删除历史/队列、不清同父认证身份，也不撤回已经发出的POST。不兼容能力声明仍由原协商返回incompatible受限状态而不是冒充legacy：其余结构有效时仍可接收合法消息，发送继续禁用。

## 字段与兼容预算

- 本人UID必须匹配请求身份，role只接受owner/member；成员为空不伪造群主。消息最多50条、seq安全整数且严格大于前序游标，沿用原消息规范化及200条可见窗口。
- hasMore省略按原兼容策略false；显式提供必须是boolean。hasMore=true却无消息无法推进本客户端游标，拒绝而不是250ms空转。不猜测未报告分页事实的旧服务是否另有积压。
- 共享空间最多16、房间最多32，沿用原字段界限。可选目录/成员缺失或null保留旧服务默认/空名单语义；已经提供却结构不符的集合不静默滤掉坏项后推进消息游标。
- 成员最多65；额外字段丢弃，头像与动态经过现有安全规范化，动态保留合法服务端updatedAt，缺失动态仍不自动清掉旧活动。元数据姓名最多200个UTF-16单元，覆盖服务端80个Unicode码点（可能占160单元），不误套消息sender.name的100单元限制。
- 好友UID最多4096且去重，请求最多200（当前服务最多返回30）；这是客户端校验预算，不是声称服务端有新的社交配额。好友请求参与者必须含本人且状态为已知三种；原好友/请求字段缺失时保留原状态。缺失createdAt可用显式now兼容，非法已提供值拒绝。
- 向已有本机好友列表仍只补充目录中尚未存在的共同好友，不自动删除、改写本机关系或批量重发请求。普通通知仍排除本人/system/静默派对心跳，保留原游标/30秒筛选及每页最多3条；启动派对历史不能经普通通知旁路补发。
- 活动字典使用无原型对象，防止特殊UID作为普通属性赋值时修改对象原型；不扫描或清除用户数据库。

## 非保证与剩余范围

- 这是完整校验后的同步提交段，不是Vue多对象事务、跨标签事务或副作用回滚。同步watcher/监听可能重入，逐字段current可阻止旧任务继续写，但不能撤销此前已被当前任务写入的字段或已发出的音乐/通知副作用。
- 草稿顶层冻结，不深度冻结消息或复制整页图片；订阅方应把消息当只读。这不是对同页面恶意插件或任意对象修改的安全沙盒。
- 历史事务接受后可能在取消等待后继续落盘；既有本地读取/投影时序及多标签竞争仍需人工验收。不承诺恰好一次、零延迟或已读。
- 只覆盖HTTP同步页及共用目录解析，服主管理/好友动作的其他响应并未全量迁移成统一Schema框架。历史/回执存储全部硬超时治理也不是本轮完成项。
- 检查为npm run check、生成后台语法和git diff --check；未编写/运行断言或无头E2E。人工验收需另获授权，重点是快速切房、启动多页静默、好友/在线动态、正常发送回执及坏页后的能力恢复。
- 后续已完成一轮源码收尾审查，见 [CHAT_ARCHITECTURE_CLOSEOUT.md](CHAT_ARCHITECTURE_CLOSEOUT.md)。没有继续拆模块，管理目录刷新也补了先解析再提交与身份检查；其余未覆盖项仍明确保留，不自动部署或启动真实数据验收。
